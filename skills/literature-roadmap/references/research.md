# 范围、筛选与路线判断

## 范围约定

从材料提炼“研究者要做什么”，不是只提取高频词。`scope.md` 顶部是唯一范围约定，包含目的、纳入/排除、方法关注点、语言、发表门槛、时间优先级、检索式、输出和确认记录。

## 交互节点（内置 grill-me 思路）

不是一次发长问卷，也不要求外部 grill-me skill。每轮围绕一个关键决定追问，先复述当前理解，再给具体边界案例和建议，让用户判断。答案含糊时继续追问其研究目的、希望解决的问题、明确不关心的对象；不为了凑轮数重复已经说清的内容。

1. **硬性条件确认。** 核对语言、允许的发表类型/CCF 等级、预印本时间范围和交付方式。分别明确“近两年优先”还是“只收近两年”、“排除非 CCF 期刊”还是“所有正式论文只收 CCF”。用户已明说的条件直接记录；默认条件只是待确认建议。
2. **scope 讨论。** 请用户讲述方向，并邀请提供已有文档、论文或讨论记录；材料可选。读完材料后总结研究目标，给具体边界案例，让用户纠正并确认。宽泛方向可以选择广泛调研，但仍须确认研究目的和排除边界。
3. **检索方案讨论，在种子检索之前。** 提出“问题关键词、同义词、方法词、排除边界”的检索组合，说明宽查询与精确查询的作用，邀请补充；同时给出 Scholar 主检索、arXiv 补充检索的分工。确认后才开始种子检索；确需探索以澄清目标时，另行展示探索问题与范围，取得明确同意后才做该项探索，不能因此跳过正式检索方案确认。
4. **种子后的主题讨论，在引用扩展之前。** 真实摘要初筛后给主题树草案，每个拟议分支配代表种子、经典问题、与选题的关系及推荐取舍。让用户决定“核心展开／保留对照／不展开”，同时确认主方向。参考可读的 Intro、Related Work 修正树；不能要求所有种子全文齐备才开始讨论。主干按主题，不按 LLM/RL 等方法划分。
5. **最后统一汇报并询问。** 给结果和覆盖限制，集中列出尚需决定的细分 scope（关联、代价、推荐取舍），以及已确认相关但全文受阻的论文（标题、链接、所属主题、摘要支持的相关性、已尝试来源）。前者问是否继续考虑，后者请用户协助下载。未读摘要的普通候选不是用户决策项；没有争议就不问范围问题，没有受阻全文就不求助。

每个问题发出后立即结束本轮，禁止在用户回答前执行后续调研。异步工具不负责阻塞执行，agent 必须自行结束轮次；没有可用询问工具就用最终回复提问。禁止等待一段时间后默认同意，也不能在等待确认期间“先”搜索 arXiv、试跑 Scholar 或扩展引用。只可在下一次用户消息到来后读取等待记录、解释当前方案、处理用户修改或登记明确确认；回复仍不解决该决定时，继续提问并结束本轮。

用户已答过的同一方案直接继承，记录原话/消息依据，不强制重复询问；这不授权尚未提出的方案。用户要求修改检索词或主题边界时，更新方案再确认，不把修改意见自动当最终批准；用户明确说“按此修改并继续”则可记录批准。已确认阶段内部自主执行。范围变动仅重审受影响论文；边界疑问放入 `scope-questions.md`，不要立刻开始新方向。继续可执行的已确认范围，收尾时统一问；若整个调研都被阻断则提前汇报并暂停。已确认成果在提问前交付，无需等用户补下载才导出。

例如 Java 反序列化防御调研中，攻击链生成、类型策略、运行时防护可以是主题；LLM/RL 是标签。是否扩展到 Python pickle 或一般 Web 防御取决于与目标的机制联系，不能因共享“反序列化”关键词无限展开。

## 种子与查询

从用户种子、旧称、同义词、问题描述、关键作者、综述与场所构造查询。包括不含 LLM/agent 的查询，寻找前驱和同问题的传统方法。记录每条查询、执行日期、页码/offset、筛选结果和下一页位置。实际分页，不将大 num 当成穷尽结果。

先核实语言、发表类型和场所，再做标题与真实摘要初筛。默认仅英文；排除经官方目录核实不在 CCF 的期刊论文，预印本豁免，优先最近两年。不能通过把已发表的不合格期刊论文另称预印本绕过筛选；正式版和预印本须关联。非 CCF 会议、白皮书等不能擅自套用“期刊排除”规则，按 scope 约定处理。小贡献和引用少不是单独排除理由。

三个决定：include、exclude、pending；include/exclude 都留理由。snippet 仅供导航；没有摘要去找出版页、作者页、预印本或正文，信息不足先留后台 pending。每批先完成可执行的筛选再扩展，不能持续把搜索结果倒进待定池。pending 区分 `screening`（agent 尚未处理）、`access_blocked`（已尝试仍缺判断材料）、`scope_question`（需要用户决定范围）、`metadata`（语言/身份/等级待核实）。只有后两类中的实际范围取舍及真正受阻项需要用户介入，普通工作积压由 agent 自行消化。

## 从正文建立主题树

论文 Intro/Related Work 的分类只是候选视角。用多篇论文核查主题边界，必要时读 Method。主题可包含多种方法；相同方法也可能分属多个主题。一个工作允许多主题归属，选择一个主主题用于默认演进连线。

优先读符合筛选规则的 CCF A/B/C 正式论文和执行日前两年预印本。查官方当前目录，记录目录版本、准确场所名、类别、链接；workshop 不继承母会议等级，投稿声明不等于录用。缺证据时 `ccf=null`，用 `ccf_status=unverified` 与 `not_listed` 区分未知和已核实非目录场所，不能仅凭空等级排除。语言看正文/出版元数据，不凭英文标题判断。

所有纳入文献尝试读 Intro、Related Work、方法概述。关键、奠基、冲突或最接近计划的工作再读实验与局限。明确区分：作者声称、本文结果、调研者推断。只写当前阅读层级能够支持的简介。

## 前后向扩展

每篇纳入论文建立 backward 和 forward 任务。参考文献结合正文引用上下文判断；被引文献从 Scholar 进入。每个新候选经过同一筛选，相关者继续追踪。同时用新术语补主题查询，避免只覆盖互相引用的一个群体。

每批记录：检索候选、去重、纳入/排除/待定、待全文、已处理/受阻队列及新增主题。队列遇到访问/接口问题标记 blocked，原因和恢复动作单列；不能标为 done 或零结果。

论文已分类不等于追踪完成。它的 backward/forward 任务须完成约定范围内的引用获取、分页和候选入队后才分别标 done，从活动队列移出但保留原记录。缺全文而无法查看参考文献时 backward 保持 blocked；Scholar 被引请求失败时 forward 保持 blocked，即使 arXiv 找到全文也不能清除该缺口。新候选自己的筛选和追踪另有队列。可执行队列为空时可以汇报阶段成果，但存在 blocked 项就不能宣称整个检索队列已完成。

## 版本与身份

核对 DOI、arXiv 基础 ID、作者、标题、出版页和版本说明。版本归入 work_family；同 DOI 通常指同版本，不同 DOI 也可能是同一工作的预印本/正式版。实质扩展可以单列，写清关系。已存在 Zotero 版本保留，不自动删除或合并。标题近似只能提示人工/agent 核对，不作为自动合并依据。

## 起源与演进

记录最早公开日期与正式发表日期。写“目前检索到最早”“代表性奠基”，不凭作者 first 声明直接写“首创”。起源检索可突破近两年的优先范围。

每条关系记录 from/to、kind、正文位置、出处、证据和是否核实。引用分类 background、baseline、tool、data、citation 不画成方法继承。仅 `improves/extends/derives` 且有证据、已核实的关键关系进入导图。推断关系暂不连线，可留在 evidence.md 供讨论。

## 完成与恢复

当约定查询和相关引用队列已经处理、补充检索没有新相关候选时，提交截至日期的覆盖审核。分类稳定只是结构变化少，不代表同类论文收全。平台额度或中断意味着保存状态待续，不是覆盖完成。

真实摘要已确认相关且符合筛选要求，即设 include、reading=abstract，放入对应主题。缺全文不退回 pending。依次尝试现有 Zotero 附件、开放正式版、预印本/作者稿、已授权机构会话；记录每次来源、结果和日期。仍受阻设 `fulltext_help=true`，在导图标“需用户帮助下载”，汇总到 `download-help.md`。尚未尝试获取不能标求助；缺摘要的访问受阻候选不作为已纳入论文挂进导图。

普通筛选积压清空后才能作收尾汇报；遇到确实受阻项可提交明确标注缺口的阶段成果。受阻的必需引用任务仍算覆盖缺口。独立记录研究覆盖、全文可用性、Zotero 同步、导图输出。恢复先读取范围约定和版本，再从未完成项继续。
