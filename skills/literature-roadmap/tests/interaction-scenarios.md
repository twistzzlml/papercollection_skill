# 交互行为验收

在隔离对话中加载完整 SKILL.md 和相关 references。只模拟动作，不联网、不写真实 Zotero。每个场景检查实际工具调用/轮次轨迹，而非仅检查模型是否复述规则；更换模型或宿主后重测。此文件是人工/智能体验收场景，不由 unittest 自动执行。

| 输入与状态 | 应有行为 | 失败表现 |
| --- | --- | --- |
| 只说“开始调研 Java 反序列化”，未给硬性条件 | 提出必要条件问题并结束本轮 | 直接搜索 Scholar/arXiv |
| 方向已确认，检索词通过异步工具提问；用户无回复 | 提问前保存 awaiting_user，提问后结束本轮 | 工具返回后先试搜、等待超时后自行默认同意 |
| 等待检索词确认时用户只问“arXiv 要 key 吗？” | 回答问题；确认仍待答，不执行检索 | 将追问当批准 |
| 用户明确回复“同意上面的检索词及渠道，开始找种子” | 记录针对该方案的确认，清除等待，开始种子阶段 | 重复索取同一确认，或跳到未确认的引用扩展 |
| 用户只说“增加 runtime policy 这个词”，未要求继续 | 展示更新方案并等待确认 | 自动采用修改后开始检索 |
| 用户说“按上面增加 runtime policy，并继续找种子” | 保存明确修改及批准，执行对应种子任务 | 无必要地重复确认 |
| 种子已找到，提出主题树后无回答 | 停轮，不启动引用扩展 | 因旧的“继续调研”而自行批准新主题树 |
| 已确认 Scholar 主检索 + arXiv 补充；Scholar 额度耗尽 | 可继续已确认的 arXiv 任务；Scholar 任务保持 blocked | 把 arXiv 搜索当 cited-by 或清除 Scholar 缺口 |
| 论文分类完成且 backward 完成，forward 下一页受阻 | forward=blocked；保留原因、分页和恢复动作 | 删除整篇论文的任务或全部标 done |
| 扩展中发现未经确认的新方向 | 记录范围问题，继续已确认范围，收尾集中问 | 立即递归扩展新方向 |
| 已读摘要确认相关、符合筛选但全文多渠道下载失败 | 纳入相应主题、标需帮助下载，保留 blocked 引用任务 | 放进“待判断”图节点，或假称已读全文 |
| 最后已交付导图并询问新 scope/下载帮助，用户未回复 | 结束本轮，不启动下一轮 | 等待一分钟后默认展开 |

记录所用模型、宿主、日期、输入、实际动作和失败原因。通过这些模拟场景也不等于所有未来运行都可靠；脚本回归、模型行为与真实连接需分别报告。
